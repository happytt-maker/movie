## 三、关键决策与理由

### 1. 契约先冻结，再谈实现

教师给的是"候选集"还是"用户列表"，决定甲要不要做全库召回、乙要不要分页。我按任务书第五节先写**候选集模式**的 v0.1，
把"仅 userId 列表"写成备用分支，这样甲乙可以立刻开工，不用等教师回复。

### 2. 核对不是"跑一遍"，而是"找出可能被问倒的地方"

复跑一致只说明可复现，不说明分数可信。所以我额外做了三件事：

- **防泄漏审计**：把任务书第五条第 4 款拆成 6 个可执行检查，全部通过；
- **换目录复跑**：排除路径/随机性副作用；
- **同分口径量化**：用"随机打破同分"做对照，检验排序是否依赖候选文件的行序。

### 3. 发现"同分假信号"，并推动修复

排序模型 `best_iteration=1`，20,660,431 行预测只有 60 余个不同分值；候选集行序又是"正样本在前、负样本在后"。
两者叠加，稳定排序会把正样本顶到 Top10 前面。量化结果：

| 同分规则 | NDCG@10 |
|---|---|
| 旧口径（按候选行序） | 0.8894（复算 0.8976） |
| 随机打破同分 | 0.8449 |
| 按 BPR 分数降序 | 0.8614 |

修复后（`CandidateSet.topk` 增加显式 tie-break、离线与接口统一、接口改为加载同一版权重），
最终模型 NDCG@10 = **0.8604**，仍比热门基线高 **16.8%**，满足任务书 ≥10% 的要求。

**代价与取舍**：分数比原报告低 2.9 个点，但这是**可解释的数**——被教师要求"打乱候选复算"时不会翻车。

### 4. 交付物按"格式一致"补齐，而不是各写各的

`top10_lsh.csv`、`top10_als.csv` 严格要求与 `top10_ranker_full.csv` 同格式（`userId,rank,movieId,score`），
这样四份结果可以直接被 `scripts/evaluate.py` 与教师的统一脚本消费。

## 四、实验记录（任务书第九节要求）

### 4.1 数据版本

| 项 | 值 |
|---|---|
| 数据集 | MovieLens 32M（官方 GroupLens） |
| 压缩包 | `ml-32m.zip`，238,950,008 字节 |
| 校验 | 解压后 4 个 CSV 的 MD5 与官方 `checksums.txt` **全部一致** |
| 规模 | 32,000,204 条评分 / 200,948 用户 / 84,432 部有评分的电影（`movies.csv` 87,585 部） |
| 划分 | 每用户按 timestamp 8:1:1 → 25,520,897 / 3,188,339 / 3,290,968 |

### 4.2 随机种子

统一 `20260907`（`configs/base.yaml`），覆盖：候选集负采样、BPR 负采样、LightGBM、Louvain 社区、流式采样、ALS `seed`。

### 4.3 软硬件环境

| 类别 | 配置 |
|---|---|
| 硬件 | i5-12500H（12 核 16 线程）/ 15.8 GB RAM / RTX 3050 Ti 4 GB（**未启用 CUDA**） |
| 系统 | Windows 11 |
| Python | 3.11.9（项目内 `.venv`） |
| 算法库 | torch 2.8.0+cpu、lightgbm 4.5.0、scipy 1.14.1、numpy 2.0.2、pandas 2.2.3、networkx 3.4.2、datasketch 1.6.5 |
| 分布式 | pyspark 3.5.3 + JDK 17.0.6（JBR），local[4] |

### 4.4 关键参数

| 模块 | 参数 |
|---|---|
