## 1. 范围

---

## 2. 输入格式

### 2.1 模式 A —— 候选集 CSV（**标准评测口径**）

```csv
userId,movieId,label
1,307,1
1,926,1
1,1952,0
```

| 列 | 类型 | 说明 |
|---|---|---|
| userId | int | 原始 MovieLens userId（1..200,948） |
| movieId | int | 原始 MovieLens movieId，不得用内部索引 |
| label | int | 1 = 测试正样本（rating ≥ 4），0 = 负样本 |

入口：`python scripts/predict.py --input <csv> --out <csv>`（**服务端目前不接外部候选文件，见 9.1**）。

### 2.2 模式 B —— 用户列表（**HTTP 接口支持的形态**）

```json
{"userIds": [1, 2, 3], "topK": 10}
```

服务端在该用户于**内置测试候选集**中的候选行内打分排序，用户必须出现在 `data/processed/candidates_test.npz`。

---

## 3. 输出格式（冻结）

```csv
userId,rank,movieId,score
1,1,307,0.097248
1,2,926,0.097248
```

| 列 | 类型 | 约束 |
|---|---|---|
| userId | int | 与输入一致 |
| rank | int | 从 1 开始，同一用户内连续不重复 |
| movieId | int | 原始 MovieLens movieId |
| score | float | 6 位小数；**同分顺序由实现决定，见 9.2** |

四条硬约束：① 每用户最多 10 条；② 同用户 movieId 不重复；③ 默认**不过滤**训练集已交互；④ UTF-8、无 BOM、逗号分隔、首行表头。

---

## 4. HTTP 接口（以 `app/main.py` 为准）

启动：`uvicorn app.main:app --host 127.0.0.1 --port 8000`，文档 `http://127.0.0.1:8000/docs`。

| 接口 | 方法 | 入参 | 返回 |
|---|---|---|---|
| `/` | GET | — | 302 跳转 `/docs` |
| `/health` | GET | — | `{status, modelsLoaded[], loadTimeSeconds, version}` |
| `/predict` | POST | `{userId, topK}` | `{userId, recommendations:[{rank,movieId,score}], latencyMs}` |
| `/predict/batch` | POST | `{userIds[], topK}` | `{totalUsers, results:[PredictResponse], totalLatencyMs}` |
| `/predict/batch/csv` | POST | `{userIds[], topK}` | `text/csv` 流，表头 `userId,rank,movieId,score` |
| `/evaluate` | POST | `{predFile, name}` | `{model, ndcg10, recall10, mrr10, users, latencyMs}` |
| `/movies/{movieId}` | GET | — | 电影名、类型 |
| `/sample/users` | GET | — | 样例用户列表 |

约束：`topK` ∈ [1, 100]；`userIds` 长度 ∈ [1, 200000]。

```bash
curl -X POST http://127.0.0.1:8000/predict -H "Content-Type: application/json" \
     -d '{"userId": 1, "topK": 10}'
```

## 5. 前端对接（乙）

| 项 | 值 |
|---|---|
| 数据源开关 | `web/.env.local`：`VITE_DATA_SOURCE=api` / `static` |
| 代理 | `/api` → `VITE_PROXY_TARGET`（默认 `http://127.0.0.1:8000`），避免 CORS |
| 前端调用 | `GET /health`、`POST /predict`、`GET /metrics`（可选） |
| `/metrics` 缺失 | 实测 404，前端**静默回退**到 `web/public/data/metrics.json` |
| 字段容错 | `client.js` 兼容 `items/results/recommendations/data` 等包装 |

---

## 6. 异常约定

| 场景 | HTTP | 响应 |
|---|---|---|
| userId 不在候选集 | 404 / 500 | FastAPI `detail` 说明原因 |
| topK 越界 / 缺字段 | 422 | Pydantic 校验错误体 |
| 启动期请求 | 503 左右 | 模型未加载完，重试即可 |

前端对 `/predict` 失败有兜底：退回本地快照并标注 `fallbackReason`。

## 9. 已知限制（v1.0 必须写明）

### 9.1 服务端不支持外部候选文件

`app/models.py` 的 `predict_single` 通过 `get_candidates_for_user` 读取**内置测试候选集**，
接口只能对 `candidates_test.npz` 里的用户与候选行打分。教师若给**新候选文件**，只能走 CLI：

```bash
python scripts/predict.py --input 教师候选.csv --out results/top10_teacher.csv
```

> 若要服务化支持，需甲把 `predict_single` 改成接收候选行（约半天）。

### 9.2 同分规则（v1.1 已统一）

排序模型 `best_iteration=1`，全表 20,660,431 行只有 60 余个不同分值，因此**同分如何排决定了 Top10**。

**v1.1 起统一规定**：先按 `score` 降序，**同分按 BPR 分数降序**。

| 位置 | 实现 |
|---|---|
| 离线 | `CandidateSet.topk(scores, k, tiebreak=bpr)` → `np.lexsort((-bpr, -score))` |
| 接口 | `app/models.py` 同样 `np.lexsort((-bpr_scores, -lgb_scores))` |
| CLI | `scripts/predict.py` → `scripts/train_ranker.py` 的同一套逻辑 |

背景与量化见核对报告 5.5/5.6 节：旧口径（按候选行序）会把 NDCG 抬高约 0.04–0.05。

> 接口与离线目前仍在**特征复算**上存在微小差异（同一批候选，Top10 约 8.5/10 条目一致），
> 彻底一致需接口复用 `src/features.py`（见核对报告 7.3）。
