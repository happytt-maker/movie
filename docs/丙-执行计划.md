### 2.2 排序模型落盘（P0，最大风险点）

**已核实事实**：`scripts/train_ranker.py` 训练完只写 `top10_*.csv` / `metrics_*.json` / `importance_*.json`，**没有保存 booster**。也就是说现在线上只能复现 BPR 的 0.8562，复现不了 0.8894。

**改法（8 行代码，改在 train_ranker.py 训练结束处）**

```python
models_dir = resolve(cfg["paths"]["models_dir"])
booster.save_model(str(models_dir / f"{args.name}.txt"), num_iteration=booster.best_iteration)
json.dump({
    "name": args.name,
    "features": names,               # 顺序必须固定，加载端按此堆列
    "best_iteration": int(booster.best_iteration or 0),
    "lightgbm": lgb.__version__,
    "seed": seed,
    "train_users": args.train_users,
    "trained_at": time.strftime("%Y-%m-%d %H:%M:%S"),
}, open(models_dir / f"{args.name}.meta.json", "w", encoding="utf-8"), ensure_ascii=False, indent=2)
```

**给甲的加载说明**（写进契约附录）：

```python
booster = lgb.Booster(model_file="models/ranker_full.txt")
meta = json.load(open("models/ranker_full.meta.json"))
X = np.column_stack([feats[n] for n in meta["features"]])   # 顺序不能错
score = booster.predict(X, num_iteration=meta["best_iteration"])
```

> 注意：文件用 `.txt`（文本模型）而不是 `.pkl`，跨机器、跨 lightgbm 版本更稳，镜像里也不用装 joblib。

### 一个必须写进核对报告的发现：LSH 结果的"行序假信号"

第一版 `top10_lsh.csv` 直接按邻居相似度求和、同分按候选集行序排，评测出 **0.9108**——
比最终模型还高。排查发现：

- 候选集里每行顺序是「正样本在前、负样本在后」；
- 头部邻居只覆盖 5.2% 的候选行，其余分数全为 0；
- 于是"空分数"被行序排到了前面，正样本自动进 Top10 —— 这是**评价口径泄漏**，不是模型能力。

把同分规则改成"按条目热度"后，随机打破同分的对照实验完全一致（0.8177 vs 0.8177），
分数落到 0.8175，位于热门基线 0.7363 与 BPR 0.8562 之间，符合"召回模块弱于学习型排序"的预期。

> 教训：任何"Top10 文件"都要用**随机打破同分**复算一次，差异大就说明排序依赖了行序。
> 这条建议同样适用于甲的服务接口和乙的展示——他们都直接消费这些 CSV。
