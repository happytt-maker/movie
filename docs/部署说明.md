# 本地部署说明

本文说明如何在 Windows 上安装依赖、准备模型数据，并启动推荐系统的 FastAPI 服务和 Vue 前端。

## 环境要求

| 组件 | 要求 |
|---|---|
| Windows | x64 |
| Python | 3.12.4，与当前锁定文件对应 |
| Node.js | 18 或更高版本 |
| Java | 17；仅运行 Spark ALS 时需要 |
| 内存 | 推荐 16 GB；数据准备、排序特征和模型训练会占用较多内存 |

当前验证环境为 Python 3.12.4、Node.js 22.16.0、PySpark 3.5.3、Java 17.0.20.1。PyTorch 锁定文件对应 CPU 版本；如需 CUDA，应先按本机 CUDA 环境安装匹配的 PyTorch 版本。

## 安装依赖

在仓库根目录打开 PowerShell：

    py -3.12 -m venv .venv
    .\.venv\Scripts\python.exe -m pip install --upgrade pip
    .\.venv\Scripts\python.exe -m pip install -r requirements.txt
    cd web
    npm.cmd ci
    cd ..

项目依赖版本均固定在 requirements.txt；前端依赖则由 web/package-lock.json 固定。数据集不随仓库提交。

## 准备模型与数据

从 [GroupLens MovieLens 32M 页面](https://grouplens.org/datasets/movielens/32m/) 下载并解压，将 ratings.csv 和 movies.csv 放到 data/ml-32m/。

启动 API 前，模型和处理文件必须齐全：

- models/bpr_mf.pt
- data/processed/train.npz
- data/processed/vocab.npz
- data/processed/candidates_test.npz
- data/features/valid.npz

从原始 MovieLens 数据生成基础划分：

    .\.venv\Scripts\python.exe scripts\prepare_data.py

若仓库尚无 BPR 权重，训练并生成推理权重：

    .\.venv\Scripts\python.exe -m src.ranking.bpr --mode all --epochs 4 --model-name bpr_mf
    .\.venv\Scripts\python.exe -m src.ranking.bpr --mode predict --model-name bpr_mf

生成 LightGBM 服务所需的验证集特征：

    .\.venv\Scripts\python.exe scripts\build_features.py --split valid

前端静态演示数据已放在 web/public/data/。重新导出前端快照时运行 web/scripts/export_web_data.py；该操作会重写 JSON 快照。

## 启动与停止

当上面的模型和处理文件都已生成后，在仓库根目录执行：

    .\.venv\Scripts\python.exe scripts\start_all.py

启动脚本会检查必需文件、创建 data/features/、data/processed/、data/spark/ 和 results/ 目录，并同时启动后端 API 和前端开发服务。

| 服务 | 地址 |
|---|---|
| 前端 | <http://127.0.0.1:5173> |
| API 文档 | <http://127.0.0.1:8001/docs> |
| 健康检查 | <http://127.0.0.1:8001/health> |

在启动窗口按 Ctrl+C 会停止两个服务。端口已占用时，可调整启动参数，例如 --api-port 8010 --web-port 5174。

若只想预览前端静态快照、暂时没有模型文件：

    .\.venv\Scripts\python.exe scripts\start_all.py --frontend-only

此模式只启动 Vite 前端并使用 web/public/data/ 的静态数据。

本机已用该模式成功启动前端，`http://127.0.0.1:5173/` 返回 HTTP 200。当前缺少上文列出的 BPR 权重与处理特征文件，因此完整 API + 前端模式会由启动脚本预检并提示缺失项；不能把 Swagger 路由文档可打开等同于在线推荐已就绪。

## Windows 上运行 Spark

需要额外设置 Java 与 PySpark 变量。安装 Java 17 后，在运行 Spark 的 PowerShell 窗口设置：

    $env:JAVA_HOME = "C:\path\to\jdk-17"
    $env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
    $env:SPARK_HOME = (Resolve-Path ".venv\Lib\site-packages\pyspark").Path
    $env:PYSPARK_PYTHON = (Resolve-Path ".venv\Scripts\python.exe").Path

ALS 的数据准备、命令和错误排查见 docs/spark-setup.md。

## 排错

- API 所需模型或处理数据尚未生成：按“准备模型与数据”步骤生成列表中的文件。
- 找不到 npm.cmd：安装 Node.js 18+，然后重新打开 PowerShell。
- 5173 或 8001 被占用：给启动脚本传入 --web-port 或 --api-port。
- Spark 报 Bad pathname：将项目和数据移动到不含中文及空格的路径。
- spark-submit 找不到 jars：设置 SPARK_HOME 为虚拟环境中的 PySpark 目录。
- PyTorch CUDA 报错：先检查 CUDA 与 PyTorch wheel 匹配；CPU 运行可不配置 CUDA。
