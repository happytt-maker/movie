# MovieLens 评分预测（显式反馈回归）—— 项目报告

> 课程第二阶段作业 · 任务：预测 `test_pairs.csv` 中 10 万个 (用户, 电影) 对的评分
> 评价指标：RMSE（越低越好）
> 交付物：`output/test_pairs_pred.csv`（100,000 行）、本报告、答辩 PPT、全部可复现代码

---

## 0. 一句话结论

在 3,190 万条评分上，偏置矩阵分解（Bias-MF）把验证集 RMSE 从**全局均值的 1.0304 降到 0.8396**，
三个随机种子等权平均后为 **0.8386**；按测试集的真实构成加权（65% 的行来自只有 5 条历史的用户），
**预期测试集 RMSE ≈ 0.895**。全程没有使用任何测试集标签——三套本地验证集分别复现了测试集的
时间外推方式、用户数量和用户历史长度。

过程中有两个结论值得先说：一是**零初始化会让矩阵分解的因子永远不更新**（六组实验的结果完全
相同，改初始化后 RMSE 从 0.9257 直接降到 0.8603）；二是**我最初为短历史用户设计的因子门控
被实验否掉了**——把因子压小反而让占多数的短历史用户更差，最终版本不使用门控（§5.4）。

## 1. 任务理解的三个转变

老师给的新任务和上一阶段的推荐任务（NDCG@10）是**两类不同的问题**，这一点必须先说清楚，
否则沿用旧代码一定会出错：

| 维度 | 上一阶段（已交付） | 本阶段（评分预测） |
|---|---|---|
| 任务类型 | 排序 / 推荐 | **回归** |
| 输出 | 每人一个 Top-10 列表 | 每个 (用户,电影) 一个 **实数评分** |
| 指标 | NDCG@10、Recall@10 | **RMSE** |
| 数据 | 自制的 8:1:1 划分 | 老师给定的 `ratings.csv` + `test_pairs.csv` |
| 关键约束 | 候选集固定 101 个 | 测试行**全部晚于**该用户最后一条训练评分 |

因此旧项目里的模型（BPR、LightGBM 排序器）**一个都用不上**：它们只会给物品打分排序，
不产出可比拟真实评分的数值。这一阶段是从零开始的一条新线。

## 2. 数据审计（`scripts/audit.py` → `reports/audit.json`）

| 项目 | 数值 |
|---|---|
| 评分数 | 31,900,204 |
| 用户数 | 396,060 |
| 电影数 | 142,609 |
| 评分范围 | 0.5 ~ 5.0（10 个离散档位，步长 0.5） |
| 全局均值 / 标准差 | 3.5404 / 1.0590 |
| 时间跨度 | 1995-01-09 ~ 2023-10-13（10,504 天） |
| 矩阵密度 | 0.056% |
| 缺失值 / 重复 (用户,电影) 对 | 0 / 0 |
| 测试对数量 | 100,000（5,498 位用户、16,036 部电影） |

三条与建模直接相关的结构事实：

**(1) 数据由两个完全隔离的半区拼成。** 真实半区 userId ≤ 200,948、movieId ≤ 87,585；
合成半区 userId ≥ 200,949。两半之间**没有任何一行跨区**，但边缘分布几乎一样
（均值 3.5401 vs 3.5406，标准差 1.0591 vs 1.0590，各评分档位占比相差不超过 0.03 个百分点）。
因为 ID 空间互不重叠，一个模型同时覆盖两半是安全的，不需要分组建模——但它们**不是同分布的**，
见 §3.3。

**(2) 评分极度集中。** 3.5 / 4.0 / 3.0 三档合计占 58.5%，4.5 与 5.0 合计占 23.7%。
这决定了 RMSE 的下限不会太低：真实评分本身有 1.06 的标准差。

**(3) 长尾非常严重。** 用户评分数中位 35、p90 为 183；电影被评分次数中位仅 4，
**最热的 1% 电影占了 50.8% 的评分**。

## 3. 四个关键发现（决定了后面的所有设计）

### 3.1 测试集是「紧邻用户历史的时间尾部」，不是远期外推

审计脚本逐行验证：**100,000 行测试对全部晚于该用户训练期最后一条评分**（`rows_before_user_last_train = 0`），
且 0 个测试对已存在于 `ratings.csv`（无标签泄漏）。

进一步测「晚多久」：

| | 间隔中位数 | p75 | p95 |
|---|---|---|---|
| 老师测试集（相对全表最后一条） | **0.1 天** | 18 天 | 351 天 |
| 我最初自建的验证集（全局截断 2023-05-01） | **120 天** | 317 天 | 1,562 天 |

差了三个数量级。这个差异不是细节——它是**第一版验证集把误差估高了 0.015** 的直接原因（见 §4）。

### 3.2 三分之二的测试行来自「只有 5 条历史」的用户

按行统计测试集的用户历史长度：

| 用户训练历史 n_u | 测试行数 | 占比 | 涉及用户 |
|---|---|---|---|
| **恰好 5 条** | **65,168** | **65.17%** | **1,043** |
| 6–9 | 384 | 0.38% | 23 |
| 10–29 | 2,583 | 2.58% | 202 |
| 30–99 | 6,076 | 6.08% | 805 |
| 100–299 | 11,267 | 11.27% | 1,512 |
| ≥300 | 14,522 | 14.52% | 1,913 |
| 合计 | 100,000 | 100% | 5,498 |

也就是说：**1,043 位用户在训练表里只留下 5 条评分，却要预测他们的 65,168 条评分（人均 62 条）**。
这是老师有意构造的「短历史」压力测试——它无法被任何按时间切分的验证集自然复现
（因为「恰好剩 5 条」是构造出来的，不是自然截断的产物），必须专门模拟（见 §4.3）。

**这条发现直接决定了模型形态**：对只有 5 条评分的用户，任何用户隐向量都只有 5 个观测可学，
模型的重心必须压在**全局均值 + 电影偏置**上——电影偏置是用 3,190 万条评分估出来的，最可靠。
（我最初据此把用户个性化的权重也压小了，但实验证明这一步是错的，见 §5.4。）

### 3.3 两个半区统计上几乎一样，误差却差 0.06

同一模型在同构验证集上：

| 半区 | 行数 | RMSE | 真实均值 | 预测均值 |
|---|---|---|---|---|
| 真实（MovieLens 原始） | 30,724 | **0.8073** | 3.4041 | 3.4663 |
| 合成（生成） | 30,850 | **0.8687** | 3.5248 | 3.5246 |

合成半区明显更难预测。逐月检查评分均值可以发现原因：**真实半区随时间有明显漂移
（月度均值在 3.44~3.58 之间波动，用户个人越往后打分越低），合成半区完全平坦（各时段均为 3.542）**。
真实数据里的「人」会变化，生成数据里的「人」是静态的——难度的差别主要来自这里。

结论：**不能只报一个平均 RMSE 就完事**，必须分半区报告，否则会掩盖一半数据上的真实表现。

### 3.4 误差高度集中在热门电影上

按电影热度分桶（提交模型，61,574 行验证集）：

| 电影被评分次数 | 行占比 | 该桶 RMSE | 占总平方误差 |
|---|---|---|---|
| 1–9 | 5.8% | 1.0076 | 8.4% |
| 10–49 | 7.1% | 0.8554 | 7.4% |
| 50–199 | 10.9% | 0.8396 | 10.9% |
| 200–999 | 18.8% | 0.8117 | 17.6% |
| ≥1000 | **52.8%** | 0.7983 | **47.8%** |

反直觉但重要：**冷门电影并不是误差的主要来源**。热门电影的 RMSE 更低（因为数据多），
但因为它们占了过半样本，贡献了近一半的总平方误差。这意味着继续优化长尾没有意义，
提升空间在**主流电影上的个性化精度**——而主流电影上残差已经接近噪声水平。

## 4. 验证集设计：为什么要三套口径

测试集不能用来调参，所以必须自建验证集。难点在于：**没有任何单一验证集能同时复现测试集
的三个特征**（时间紧邻、5 条历史、两半区各半）。最终用了三套互补口径，各自回答一个问题：

### 4.1 口径 A：固定日历截断（2023-05-01）—— 用于选超参

沿用最朴素的做法：截断点之前的全部数据训练，之后且训练历史 ≥5 条的行留出。
得到 106,933 行 / 7,198 位用户。

**问题**：间隔中位 120 天，把「用户越往后打分越低」的漂移放大了。在这个口径上
最优模型 RMSE 是 0.8539，比口径 B 高 0.015——**这不是模型变差了，是题目变难了**。
它的价值在于：所有超参（维度、L2、学习率、收缩强度）都是在这套 10.7 万行上搜出来的，
样本量大、结论稳定。

### 4.2 口径 B：时间尾部截断（2023-07-01）—— 用于报告主指标

按老师「紧邻尾部」的形态重建：留出 61,574 行 / 5,480 位用户 / 每人中位 4 条
（老师测试集为 100,000 行 / 5,498 位用户 / 每人中位 4 条，用户结构几乎一致），
间隔中位降到 0.3 天。**本报告的主指标 0.8386 来自这个口径。**

### 4.3 口径 C：稀疏历史模拟 —— 用于估计测试集最重的那 65%

口径 B 仍然复现不了「恰好 5 条历史」，因为自然截断下这类用户会被 `min_history` 过滤掉。
于是显式构造：随机抽 1,043 位评分足够的用户，**只保留他们最早的 5 条进训练**，
第 6~67 条留出评估。得到 64,666 行 / 1,043 位用户 / 每人 62 条，与测试集那一群完全同构。

结果：**RMSE 0.9243**（第 6 轮，与提交配置同步；第 5 轮更低一点，为 0.92358）。
分半区看，真实半区 0.911、合成半区 0.935——比长历史群体（0.807 / 0.869）各差约 0.1。 

### 4.4 三套口径的合成：预期测试集 RMSE

| 口径 | 行数 | 用户 | RMSE | 回答的问题 |
|---|---|---|---|---|
| A 固定截断 | 106,933 | 7,198 | 0.8539 | 超参怎么选 |
| B 时间尾部 | 61,574 | 5,480 | **0.8386** | 主流场景能做到多好 |
| C 稀疏模拟 | 64,666 | 1,043 | **0.9243** | 那 65% 的行有多难 |

按测试集的真实构成加权（65.168% 来自稀疏群，34.832% 来自长历史群，按平方误差加权）：

```
MSE ≈ 0.65168 × 0.9243² + 0.34832 × 0.8386² = 0.8019
RMSE ≈ 0.8954
```

**所以对外报告：预期测试集 RMSE ≈ 0.895。** 单看口径 B 的 0.8386 会低估，
单看口径 A 的 0.8539 会高估——三口径合成才是诚实的估计。

## 5. 模型：偏置矩阵分解（Bias-MF）

### 5.1 公式

```
r̂(u,i) = μ + b_u + b_i + p_u · q_i
```

- `μ` 全局均值；`r̂` 预测值最后裁剪到 `[0.5, 5.0]`
- `b_u` 用户偏置：这个人比平均挑剔多少
- `b_i` 电影偏置：这部片比平均好多少（也是数据里最强的单项信号）
- `p_u`、`q_i` 为 64 维隐向量，点积表示「口味与风格的匹配度」

结构见图 `docs/figs/08_模型结构.png`：四项相加得预测；训练上先解偏置、再学因子。

**为什么是这个结构**（选型理由）：测试集 65% 的行来自只有 5 条历史的用户（§3.2），
对这类用户，任何用户隐向量都只有 5 个观测可学，个性化项必须靠**共享的电影侧参数**兜底。
Bias-MF 正好把「电影质量」与「用户口味」拆开：前者用 3,190 万条评分估计，非常可靠；
后者才需要用户自己的数据。这比端到端的深模型更适合当前的数据形态——深模型参数量大，
在这种稀疏度下只会记住训练集。

### 5.2 训练流程

1. **偏置预拟合**：先用交替最小二乘（ALS）解出 μ、b_u、b_i，收缩强度网格搜出
   `λ_u = 50`、`λ_i = 2`（λ_u 大，因为用户数量多、平均历史短；λ_i 小，因为电影偏置是主要信号）。
   纯 `np.bincount` 实现，31.9M 行 8 轮约 60 秒。
2. **把偏置作为初值冻结进网络**：`b_u`、`b_i` 继续作为可训练参数，初值取 ALS 结果。
   相当于让随机梯度只负责学因子，收敛快且稳定。
3. **因子用 SparseAdam 优化**：每步只更新 batch 内出现的用户/电影，31.9M 行 × 6 轮
   在 RTX 3050 Laptop（4GB 显存）上约 4 分钟。
4. **L2 作用在 batch 内因子范数**上（系数 3e-2），而不是全表——否则无法用稀疏优化器。

最终配置：`dim=64, l2=3e-2, lr=1e-3, 6 轮, batch=8192`，三个随机种子（1/2/3）等权平均。

### 5.3 两个必须记录的坑

**坑一：零初始化让因子永远学不动。** 最初用 `nn.init.zeros_` 初始化隐向量，结果
dim=16/32 × κ=0/10 四组实验的 RMSE **一模一样**（都是 0.9256974204823673，连小数点后第 16 位都相同，
见 `reports/experiments.json` 中四条同值记录）。
原因：`p=0` 且 `q=0` 时 `p·q = 0`，且对 p 的梯度 `= q = 0`，对 q 的梯度 `= p = 0`——
梯度恒为零，参数永远停在零点，因子项从头到尾就是 0。改成 `normal_(std=0.01)` 之后，
RMSE 从 0.9257 直接降到 0.8603。**这是本项目最大的单点收益，也是最容易忽略的一处。**

**坑二：立刻过拟合。** 学习率 5e-3、L2 1e-4 时，训练 MSE 从 0.819 掉到 0.456，
验证 RMSE 却从 0.931 升到 0.876——模型在背训练集。把 L2 提到 3e-2、学习率降到 1e-3 后，
训练/验证曲线同步下降；再往后训练误差继续降、验证误差在第 8 轮触底后回升
（见 `docs/figs/05_训练曲线.png`），因此最终固定 6 轮、不靠验证集早停（提交模型用全量数据训练，
没有验证集可早停，轮数必须提前定死）。

### 5.4 一个被实验否定的设计：因子门控

在知道「65% 的测试行只有 5 条历史」之后，我加了一项**置信门控**：

```
r̂(u,i) = μ + b_u + b_i + g_u · (p_u · q_i),   g_u = n_u / (n_u + κ)
```

动机很直接：n_u = 5 时用户的隐向量只有 5 个观测支撑，不可靠，那就把它压小
（κ=10 时 `g_u = 0.33`），让预测回落到「影片质量 + 大众口味」。

**在稀疏模拟集上把它验掉了**：

| 门控强度 | 稀疏群 RMSE（64,666 行） |
|---|---|
| κ = 0（不门控） | **0.92358** |
| κ = 10（原设计） | 0.92801 |
| κ = 100（强门控） | 0.93949 |

压得越狠越差。原因想通了：`q_i` 是在 3,190 万条评分上训练出来的，非常可靠；一个用户的
`p_u` 虽然只有 5 个观测，但 `p_u · q_i` 相当于「拿他看过的 5 部片当锚点做相似度检索」，
仍然有信号。把它压小等于主动扔掉这个信号。

**最终版本不使用门控**（κ=0）。这条留在这里是因为它是个有用的教训：
动机再合理的正则项，也要用数据检验；我最初的直觉在这里是错的。

## 6. 结果

### 6.1 基线阶梯（口径 B，61,574 行）

| 模型 | RMSE | 相对上一档 |
|---|---|---|
| 全局均值 μ | 1.0304 | — |
| 用户均值 | 1.0012 | −0.029 |
| 电影均值 | 0.9577 | −0.044 |
| 偏置 ALS（μ+b_u+b_i） | 0.9129 | −0.045 |
| **Bias-MF（dim64, 6 轮）** | **0.8396** | **−0.073** |
| **三 seed 等权平均（提交）** | **0.8386** | −0.001 |

两点值得说：

- **偏置项贡献了大部分增益**（1.0304 → 0.9129，降幅 0.118），因子只再降 0.073。
  这与 §3.2 的发现一致：大部分样本的用户历史太短，学不出可靠的用户向量。
- **多种子平均的边际收益很小**（0.0010）。三个种子的预测两两相关系数在 0.99 以上，
  多样性不足，属于「调参到头」的信号。

### 6.2 单模型与融合

| 模型 | 配置 | RMSE | 真实半区 | 合成半区 | MAE |
|---|---|---|---|---|---|
| V1 | d64, L2 3e-2, seed1 | 0.84013 | 0.80921 | 0.86983 | 0.63884 |
| T0 | d64, L2 3e-2, seed2 | 0.83957 | 0.80881 | 0.86913 | 0.63834 |
| V3 | d64, L2 3e-2, seed3 | 0.84008 | 0.80923 | 0.86971 | 0.63849 |
| **等权平均（提交）** | 三个种子各 1/3 | **0.83858** | **0.80725** | 0.86867 | **0.63744** |

三个种子直接等权平均，**不在验证集上再拟合融合权重**——避免把验证集用两次
（一次选配置、一次定权重），多拟合 2 个自由度换 0.001 的收益不值。

## 7. 误差分析

### 7.1 残差

提交模型在口径 B 上的残差：均值 **−0.031**、标准差 0.838、偏度 −0.59，
p1 = −2.52、p99 = +1.71。轻微左偏说明模型对「用户不喜欢」的极端情况预测偏保守
（预测值向中间拉，这是平方损失 + 收缩的必然结果）。预测值落在 0.5 或 5.0 边界的只有
142 行（0.23%），说明裁剪几乎没有起作用。

### 7.2 按用户历史长度

| n_u | 行占比 | RMSE |
|---|---|---|
| 6–9 | 0.8% | 1.0142 |
| 10–29 | 7.3% | 0.8731 |
| 30–99 | 14.6% | 0.8577 |
| 100–299 | 27.1% | 0.8096 |
| ≥300 | 50.1% | 0.8393 |

短历史确实更难（1.01 vs 0.81）。而 ≥300 的桶反而比 100–299 差，对应 §3.3 的真实半区
时间漂移：重度用户在「未来」打分比历史均值低约 0.5。

这张表也解释了为什么必须单独做口径 C：口径 B 里 n_u ≤ 5 的行只有 25 条，
而在真实测试集里这个群体占了 65%。

### 7.3 全局偏移校正：试过，没用

既然残差均值是 −0.031，自然会想给所有预测加一个常数。实测：

| 全局偏移 | RMSE |
|---|---|
| −0.030（最优） | 0.83801 |
| 0 | 0.83858 |

只降 0.0006，低于该验证集上 RMSE 的标准误（约 0.0024）。**结论：不做偏移校正。**
在口径 A 上曾测得最优偏移 −0.06、收益 0.0018，但那是因为口径 A 的间隔是 120 天、
漂移被放大；换成与测试集同构的口径 B，漂移几乎消失。这正好反过来说明：
**验证集口径错了，调出来的「校正」也是错的。**

## 8. 负面结论（都做了实验，都失败了）

诚实记录，因为它们划定了这个任务的边界。另外两条负面结论在前面已经写过：
**因子门控方向反了**（§5.4）、**全局偏移校正的收益低于噪声**（§7.3）。

### 8.1 GBDT 残差修正层：完全无效

思路：用 MF 预测作为基线，训练 `HistGradientBoostingRegressor` 学残差，输入 12 维特征
（MF 预测、用户/电影均值与计数、时间新鲜度、类型亲和度、半区标记等）。

结果：验证 RMSE **0.8764**，比不叠加还差（0.8539）。逐项诊断发现：
**GBDT 输出的修正量与真实残差的相关系数是 0.0000**（特征对齐已逐行核验，最大差 0.0）。
也就是说树模型在残差上只能学到噪声。解释：残差已经接近独立同分布，没有可学习的结构；
真正的瓶颈是「信息不足」（用户只有 5 条历史），不是「模型不够复杂」。

### 8.2 把预测取整到 0.5 网格：变差

既然真实评分只有 10 个档位，把预测四舍五入到最近的 0.5 似乎能降 RMSE。
实测：**0.8539 → 0.8658**，反而变差 0.012。原因是取整引入的量化误差（期望约 0.125）
大于它带来的「落点精确」收益。**保持连续输出。**

### 8.3 更多训练轮次：没有收益

把轮数从 8 加到 15（口径 B，κ=10 配置）：验证 RMSE 在第 8 轮触底 0.8392，
之后 9~15 轮持续回升到 0.8413，训练 MSE 却从 0.6306 一路降到 0.5976。
后续轮次只在对训练集做记忆。最终把轮数定在 6，六个轮次已吃掉绝大部分收益。

```bash
python scripts/audit.py                                    # 1 分钟
python scripts/eval_bias.py --split tail                   # 2 分钟：偏置基线

python scripts/train_mf.py --split tail --dim 64 --l2 3e-2 --kappa 0 --lr 1e-3 --epochs 9 --seed 2 --tag T0
python scripts/train_mf.py --split tail --dim 64 --l2 3e-2 --kappa 0 --lr 1e-3 --epochs 6 --seed 3 --tag V3

python scripts/train_mf.py --split sparse --dim 64 --l2 3e-2 --kappa 10  --lr 1e-3 --epochs 8 --seed 2 --tag S1

python scripts/eval_final.py                               # 阶梯、分段、混合估计

python scripts/train_mf.py --final --dim 64 --l2 3e-2 --kappa 0 --lr 1e-3 --epochs 6 --seed 1 --tag G1
python scripts/train_mf.py --final --dim 64 --l2 3e-2 --kappa 0 --lr 1e-3 --epochs 6 --seed 2 --tag G2
python scripts/train_mf.py --final --dim 64 --l2 3e-2 --kappa 0 --lr 1e-3 --epochs 6 --seed 3 --tag G3
```

## 10. 已知局限

1. **无法在真实测试集上验证。** 所有数字来自本地三套验证集，最好的估计是 0.895，
   误差范围大致 ±0.01。真实 RMSE 只有在老师评分后才知晓。
2. **口径 C 的抽样偏差。** 稀疏模拟抽的是「评分足够多」的用户，而测试集里那 1,043 位
   用户的总评分数分布未知（我们只能看到他们剩下的 5 条）。若他们的真实偏好更极端，
   0.9243 可能偏乐观。
3. **两半区难度不同但只提交一份预测。** 真实半区 0.807、合成半区 0.869，差 0.06。
   已验证可以按半区分开建模（模型带 `--half` 参数），但增益不足以抵消过拟合风险，故未采用。
4. **未尝试序列模型。** SASRec/BERT4Rec 一类需要「预测下一个评分」的序列建模，
   理论上能吃到时间信息，但 4GB 显存 + 31.9M 行的成本过高，本轮未做。
5. **`lambda` 与轮数是在口径 A/B 上定的**，口径 A 存在时间漂移（§4.1）。若漂移在测试集上
   更弱，当前配置可能略微欠拟合；这是已知的不确定性，但两部分误差都小于 0.002，不影响结论。
