# 第二阶段任务：电影评分预测（显式反馈回归）

> 从「排序」到「回归」——上一阶段产出的是推荐顺序，这一阶段产出的是**可比拟真实评分的数值**，按 **RMSE** 评分。

本目录是第二阶段（评分预测）的完整交付：数据审计、验证集设计、模型实现、误差分析、否定结论与提交文件。
上一阶段（排序 / 服务化）的代码仍在仓库根目录的其他目录中，**本阶段不复用**它们——排序模型只输出顺序，给不出一个可比拟真实评分的实数。

---

## 1. 任务与数据

| 项 | 内容 |
|---|---|
| 输入 | 老师给定的 `ratings.csv`（31,900,204 行）+ `test_pairs.csv`（100,000 行） |
| 输出 | 每个 `(userId, movieId)` 一个预测评分，落在 `[0.5, 5.0]` |
| 指标 | RMSE（越低越好） |
| 评分档位 | 只有 10 个离散值（0.5 / 1.0 / … / 5.0），3.0–4.0 三档占 58.5% |

**三条硬约束**（决定建模方式）：

1. 10 万测试行**全部晚于**该用户最后一条训练评分——时间外推，不是随机留出；
2. 0 个测试对与 `ratings.csv` 重叠，无标签泄漏；
3. 输出必须是一个落在 `[0.5, 5.0]` 区间内的实数。

**两个互不相通的半区**：`userId ≤ 200,948` 为真实数据、`≥ 200,949` 为合成数据，零跨区行；两区边缘分布几乎一致（均值差 0.0005、各档位占比差 ≤ 0.03 个百分点），但**难度不同**（真实区 RMSE 0.807、合成区 0.869）。

---

## 2. 关键发现

### 2.1 三分之二的测试行只有 5 条历史

10 万测试行里有 **65,168 行（65.2%）来自仅 1,043 位「训练表里恰好 5 条评分」的用户**，人均要预测 62 条。

```
历史条数   =5      6–9     10–29   30–99   100–299  ≥300
测试行数   65,168  384     2,583   6,076   11,267   14,522
用户数     1,043   23      202     805     1,512    1,913
```

这条结构决定了后面所有设计：**模型重心必须压在电影侧参数上**（`b_i`、`q_i` 能用 3,190 万条评分估稳），验证集必须专门模拟这批用户。

### 2.2 测试行相对用户最后一条评分，间隔中位只有 0.1 天

第一版验证集我按 `2023-05-01` 做固定日历截断，切出来的间隔中位是 **120 天**——比真实测试集大三个数量级，会把"用户越往后打分越低"的时间漂移放大，从而**高估误差 0.015**。

---

## 3. 验证集：三个口径，缺一不可

| 口径 | 构造方式 | 留出行数 | 用户数 | RMSE | 回答什么问题 |
|---|---|---|---|---|---|
| A 固定日历截断 | `timestamp < 2023-05-01` | 106,933 | 7,198 | 0.8539 | 调超参、比模型版本相对优劣 |
| B 时间尾部截断 | `timestamp < 2023-07-01` | 61,574 | 5,480 | **0.8386** | 报告主指标（用户结构对齐测试集） |
| C 稀疏历史模拟 | 每人只留 5 条历史 | 64,666 | 1,043 | 0.9243 | 那 65% 的行到底有多难 |

口径 B 与老师测试集的用户结构对齐（5,480 人 vs 5,498 人，人均 4 条）；口径 C 显式模拟"恰好 5 条历史"，任何按时间切分的验证集都造不出这种形态。

**没有任何单一划分能同时复现测试集**，所以按测试集真实构成做混合估计：

```
MSE_期望 = 0.65168 × 0.9243² + 0.34832 × 0.8386²   →   预期测试集 RMSE ≈ 0.8954
```

> 口径错了，调出来的校正也是错的：口径 A 上「全局偏移 −0.06」的收益，到口径 B 只剩 0.0006。

---

## 4. 模型：Bias-MF

```
预测值 = μ + b_u + b_i + p_u · q_i
```

| 项 | 含义 | 估计方式 |
|---|---|---|
| `μ` | 全局均值 3.5767 | 3,190 万条直接算 |
| `b_u` | 用户偏置（打分宽严） | ALS 闭式解 |
| `b_i` | 电影偏置（片本身好坏） | ALS 闭式解，**四项里贡献最大** |
| `p_u · q_i` | 64 维隐向量内积 | SparseAdam 训练 |

**训练四步**：ALS 预拟合偏置 → 作为网络初值 → SparseAdam 只更新批内出现的向量 → 第 6 轮早停。

选它的理由是数据形态：65% 的行只有 5 条历史，只有电影侧参数能用 3,190 万条评分估稳。

### 4.1 实现中的两个坑

**坑一 · 零初始化死锁**：`dim 16/32 × κ 0/10` 四组实验的 RMSE 完全相同（0.9256974204823673，连小数点后第 16 位都一样）。
原因：`p = q = 0` 时 `p·q = 0`，对 `p` 的梯度也恒为 0，因子永远停在原点。
改为 `normal_(std=0.01)` 后，同一份数据从 0.9257 降到 0.8603。

**坑二 · 一放开就过拟合**：`lr 5e-3 + L2 1e-4` 时训练 MSE 掉到 0.456、验证升到 0.876。
改 `L2 3e-2 + lr 1e-3` 后曲线正常；15 轮曲线显示第 8 轮触底 0.83923，之后训练继续降、验证回升——是过拟合，不是欠拟合，故固定 6 轮留余量。

## 5. 结果

| 阶段 | 验证集 RMSE（口径 B） |
|---|---|
| 全局均值 | 1.0304 |
| + 用户偏置（用户均值） | 1.0012 |
| + 电影偏置（电影均值） | 0.9577 |
| 偏置 ALS（`μ + b_u + b_i`） | 0.9129 |
| **Bias-MF（单 seed）** | **0.8396** |
| **三 seed 等权** | **0.8386** |

- 三个 seed：0.84013 / 0.83957 / 0.84008，等权平均 **0.83858**（不在验证集上再拟合权重）
- 分半区：真实 0.8073 / 合成 0.8687
- **按测试集构成加权，预期测试集 RMSE ≈ 0.895**
- 偏置项贡献 0.118 的降幅、因子只再降 0.073——大部分增益来自「电影有多好」，不是「这个人多独特」

提交文件 `output/test_pairs_pred.csv`：100,000 行 × 4 列，前三列（`userId, movieId, timestamp`）与原表逐行一致，第 4 列 `rating` 为预测评分（列名与 `ratings.csv` 一致）；无缺失、无越界；均值 3.5767、标准差 0.5706、唯一值 24,457 个。

## 6. 误差分析与否定结论

误差没有集中在长尾：≥1000 条评分的电影占 52.8% 的样本、**47.8% 的平方误差**；1–9 条的长尾只占 5.8% 样本、8.4% 误差（RMSE 反而最高 1.008）。
残差均值 −0.031、标准差 0.838、偏度 −0.59，被裁到 0.5/5.0 边界的仅 142 行（0.09%）。**瓶颈是信息量，不是模型容量。**

三条否定结论（都做了实验，都写进了报告）：

| 尝试 | 结果 | 原因 |
|---|---|---|
| GBDT 残差修正层 | 0.8764，比不叠加更差 | 修正量与真实残差相关系数 **0.0000**，给定 `(u,i)` 后残差已近似纯噪声 |
| 预测取整到 0.5 网格 | 0.8539 → 0.8658 | 量化误差（平均 0.012）大于它能减少的偏差 |
| 全局偏移校正 | 最优 −0.030 只降 0.0006 | 低于验证集标准误 0.0024，换个 seed 就没了 |

还有一条：**为短历史用户设计的门控被自己的实验否定**。原假设 `g_u = n_u/(n_u+κ)` 把 `p_u` 按历史条数压小，实测稀疏群 RMSE：κ=0 为 0.92358、κ=10 为 0.92801、κ=100 为 0.93949——**压得越狠越差**。
解释：`q_i` 由 3,190 万条评分训练，非常可靠；`p_u·q_i` 相当于拿用户看过的 5 部片做相似度检索，仍有信号，压小等于主动扔掉。最终提交用 κ=0，混合预期从 0.8977 改善到 0.8954。

## 8. 复现

```bash
# 0. 环境：Python 3.10+，见 requirements.txt

# 1. 把老师给的数据放到 data/
#    data/ratings.csv      31,900,204 行
#    data/test_pairs.csv   100,000 行

# 2. 数据审计
python scripts/audit.py

# 3. 偏置预拟合 + 基线阶梯
python scripts/eval_bias.py

# 4. 验证集上选配置（--split 选口径：cutoff / tail / sparse）
python scripts/train_mf.py --split tail   --dim 64 --l2 3e-2 --kappa 0 --lr 1e-3 --epochs 6 --seed 1 --tag V1
python scripts/train_mf.py --split sparse --dim 64 --l2 3e-2 --kappa 0 --lr 1e-3 --epochs 8 --seed 2 --tag S2
python scripts/train_mf.py --split sparse --dim 64 --l2 3e-2 --kappa 10 --lr 1e-3 --epochs 8 --seed 2 --tag S1

# 5. 全量重训三个 seed（--final 不分验证集），再等权融合
python scripts/train_mf.py --final --dim 64 --l2 3e-2 --kappa 0 --lr 1e-3 --epochs 6 --seed 1 --tag G1
python scripts/train_mf.py --final --dim 64 --l2 3e-2 --kappa 0 --lr 1e-3 --epochs 6 --seed 2 --tag G2
python scripts/train_mf.py --final --dim 64 --l2 3e-2 --kappa 0 --lr 1e-3 --epochs 6 --seed 3 --tag G3
python scripts/make_submission.py --preds G1 G2 G3 --no-valid

# 6. 汇总数字与出图
python scripts/eval_final.py
python scripts/make_figs.py
python scripts/make_slide_figs.py
```

单轮约 33 秒（64 维、batch 8192、3,190 万条），六个 epoch 约 200 秒；
三个种子全量重训约 10 分钟。依据 `reports/metrics_*.json` 的 `elapsed_seconds`
（V1 为 199.8 秒／6 轮，T0 为 317.1 秒／10 轮，均由该字段反算）。

## 9. 已知局限

1. **真实测试集无法本地验证**：0.895 是按测试集构成推算的期望值，不是实测值。
2. **稀疏群是抽样模拟**：口径 C 按 1,043 人抽样，若老师那批用户的分布更偏，实际结果可能更差。
3. 两个半区难度不同（0.807 vs 0.869），而测试集里合成区占多少未知，这里按两区同分布处理。
4. 未使用评分时间戳、电影类型、标签等侧信息；纯协同过滤在「5 条历史」这一档上已接近信息上限。
